1. Instructions to the RTL / AI Coding Agent
Treat this document as the single normative implementation baseline. Generate the new integration RTL, 
memory/MMIO logic, DMA, UART, firmware build files, and simulation environment only within the boundaries 
below.
 Use the official `picorv32` module from the YosysHQ repository. Use the native memory interface of 
`picorv32`; do not use `picorv32_axi`, `picorv32_wb`, or an AXI bridge in the MVP.
 Instantiate the user-supplied accelerator as fixed IP. Do not edit its internal RTL, rename its ports, or 
redesign its PE/systolic dataflow.
 Do not enable the Zynq Processing System, PS DDR, HP ports, AXI interconnect, Linux, cache, camera input, 
second accelerator, or generic scatter-gather DMA in the MVP.
 Implement only the wrapper, interconnect, memories, DMA, UART, reset logic, system registers, and 
firmware support described here.
 All unspecified behavior is an implementation choice only when it does not change a normative rule. Do not 
invent alternative protocols, addresses, or ownership rules.
 Provide compile order, synthesis constraints, simulation files, and a short README that reproduces the same 
build.
 Do not claim accelerator correctness until the standalone fixed-IP regression and the integrated known-
matrix regression both pass.

 MMIO byte/halfword accesses are unsupported: complete with an error and no side effect.

8.3 CPU element write semantics
1. CPU owns accelerator port (DMA_OWNER=0).
2. ACC_MATRIX_SELECT, ACC_ROW, ACC_COLUMN are programmed.
3. CPU performs one aligned full-word store to ACC_WRITE_DATA.
4. If wrapper is not RUNNING/FAULT and ownership is legal:
      -> fixed-IP wr_en pulses for exactly one clock
      -> matrix_select/row/col/data are held for that event
5. Partial MMIO strobes are rejected and must not modify accelerator state.
6. A write while fixed IP is busy is rejected; it is never stalled.
8.4 START/DONE semantics
 The wrapper generates exactly one-cycle `start` pulse to the fixed IP.
 START is accepted only when the fixed IP is idle, wrapper state is IDLE, and DMA_OWNER=0.
 START while busy is rejected and does not restart or extend the fixed-IP run.

9.2 DMA transfer rules
 DMA is started only by CPU firmware.
 DMA_OWNER must be set to 1 before a DMA transfer; changing ownership while DMA is BUSY is rejected.
 No DMA completion may directly or indirectly assert accelerator START.
 For ACT_LOAD/WEIGHT_LOAD, each 32-bit memory read is split little-endian into four INT8 element writes.
 For RESULT_STORE, DMA reads accelerator result index 0..63 in row-major order, waits for each one-cycle 
read response, then writes one 32-bit result to memory.
 The fixed accelerator remains element-oriented; packing is a DMA-only implementation function.
 DMA shall use one outstanding memory read at a time.
 DMA never accesses MMIO.
 DMA validates source/destination/length before the first transfer beat.
9.3 DMA result address
For result element (row, col):
  result_index = 8*row + col
  destination_address = DMA_DST_ADDR + 4*result_index

11. Clock, Reset, and CDC
 One 100 MHz PL clock is used for PicoRV32, interconnect, BRAM control, DMA, wrapper, accelerator, and 
UART logic.
 No generated or divided clocks are used. UART timing is produced by a counter/divider in the 100 MHz 
domain.
 External reset is active-low. Internal block resets are synchronous to the 100 MHz clock.
 The wrapper shall be able to assert a local accelerator reset for at least four full cycles.
 Local accelerator reset must not corrupt CPU or DMA state unless the software explicitly requests a system 
reset.
 UART RX enters a two-flip-flop synchronizer before functional use; the raw asynchronous pin must not fan 
out elsewhere.
 Exact ZedBoard reset/UART pin numbers shall come from the final XDC and shall not be guessed by the 
coding agent.

12.1 GEMM lowering
All Conv/FC layers are lowered to:
  C[M,N] = A[M,K] × B[K,N]
Tile contract:
  A tile = 8×8 INT8
  B tile = 8×8 INT8
  C tile = 8×8 INT32
For M, N, or K not divisible by 8:
  - software zero-pads the final tile;
  - accelerator still receives exactly 8×8 operands;
  - only valid output rows/columns are consumed.
For K > 8:
  - issue ceil(K/8) accelerator STARTs;
  - each START computes one 8-term partial;
  - accumulate partials in INT32 in software.
12.2 Quantization
Parameter MVP rule
Operand type signed INT8, -128..127
Zero point 0
Quantization symmetric
Scale per-tensor; power-of-two preferred
Accumulator signed INT32
Requantization software after INT32 accumulation
Rounding nearest, ties away from zero
Saturation clip to [-128, 127]
Argmax tie lowest class index wins
Overflow model converter must prove selected INT32 paths do not 
overflow
For a nonnegative integer shift s:
  q_pos = (x + 2^(s-1)) >>> s
For a negative x:
  q_neg = -(((-x) + 2^(s-1)) >>> s)
Then:
  q = clamp(q, -128, 127)
For shift = 0:
  q = x

13. Firmware Control Flow
BOOT
  -> initialize stack/data
  -> configure UART_DIVISOR = 53
  -> clear system/ACC/DMA sticky status
  -> confirm required memory regions
  -> wait for host command
INPUT LOAD
  -> receive framed INT8 image
  -> validate length / CRC
  -> store 28x28 tensor in INPUT
INFERENCE
  -> for each lowered layer:
       * generate / stage A tile
       * acquire DMA_OWNER=1
       * DMA ACT_LOAD
       * acquire DMA_OWNER=1
       * DMA WEIGHT_LOAD
       * release DMA_OWNER
       * ACC START
       * poll ACC_STATUS.BUSY/DONE
       * acquire DMA_OWNER=1
       * DMA RESULT_STORE to OUTPUT
       * release DMA_OWNER
       * accumulate / requantize / pool / ReLU as required
  -> final FC logits
  -> argmax
  -> send RESULT frame
ERROR
  -> read SYS / ACC / DMA error
  -> abort DMA if active
  -> use accelerator local reset for accelerator FAULT
  -> use SYS_SOFT_RESET only when software can safely issue it
  -> external reset if CPU trap halts execution
Implementation note: The accelerator is not a generic CNN runtime. Firmware owns layer scheduling, K-split 
accumulation, buffer ownership, and preprocessing.

15.2 Required assertions
A1: fixed-IP START is never asserted for more than one cycle.
A2: START is accepted only when wrapper is IDLE, fixed IP not busy, DMA_OWNER=0.
A3: CPU ACC_WRITE_DATA partial-strobe writes never change accelerator storage.
A4: DMA reads use wstrb=0000; DMA memory writes use wstrb=1111.
A5: DMA never starts accelerator automatically.
A6: at most one DMA memory read is outstanding.
A7: DMA_OWNER cannot change while DMA is busy.
A8: no illegal access is stalled indefinitely.
A9: fixed-IP DONE is latched only after an accepted START.
A10: same-address CPU/DMA dual-write is never allowed.
A11: accelerator result index order is 0..63 row-major during DMA drain.
A12: timeout always reaches a bounded recovery state.
